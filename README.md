## 這個專案在做什麼

本專案想回答一個語言學與文學研究的問題：**一個句子主要讓我們「看見」一個可感知的場景，還是在談概念、心理、價值與評價？**

具體語言指句子主要描寫可感知的物件、動作、地點、人物，或讀者能直接想像的場景；抽象語言則指句子主要討論概念、價值、關係、心理狀態或評價，缺乏直接的感官指涉。這種差異可能影響讀者如何建構故事中的人物、動作與空間，也可能與敘事節奏、情緒效果和「故事形狀」有關。

因此，本專案以**句子為單位**建立一個具體／抽象二元分類器，作為探索小說語言差異的初步量化工具。必須強調：分類結果**不是**要取代細讀或文學詮釋，句子本來就常常同時具有具體與抽象成分，二元標籤只是研究上的方便。

## 資料與標註流程

- **訓練資料**：魯迅《吶喊》全部 14 篇小說，切句、清洗、去重後共 **2,394 句**。
- **應用文本**：郁達夫的〈秋河〉，用來觀察模型跨作者套用時的行為。
- **標註方式**：由本機執行的**關鍵詞規則**產生初始標籤（不是大型語言模型，也沒有呼叫外部 API）。規則比較抽象與具體線索詞的數量；平手時以引號與人稱代詞密度輔助，仍無法決定者標為 `uncertain`。這樣做的好處是每個決定都可重現、可稽覈。
- **人工複核**：從 2,029 句非 `uncertain` 句中分層抽查 **203 句**，人工判斷與規則一致 **168 句，一致率 82.76%**，35 句分歧在平衡抽樣前套用修正。
- **平衡抽樣**：排除 `uncertain` 後，兩類各抽 400 句（固定種子 42），組成 **800 句平衡樣本**，再以 80/20 分層切分為 train 640（各 320）與 test 160（各 80）。平衡抽樣方便比較模型，但也改變了原始類別比例，因此模型預測的比例**不能**直接當作文本中兩類句子的真實比例。

## 分析成果

本研究比較三種特徵搭配邏輯迴歸的表現（測試集 160 句）：

| 模型 | 特徵 | Accuracy | Macro F1 |
|---|---|---|---|
| A | 詞頻（CountVectorizer, max_features=200） | 0.4938 | 0.3412 |
| B | 詞量 TF-IDF（max_features=2000, ngram 1–2） | 0.5125 | 0.3605 |
| C | **字元 TF-IDF（ngram 2–5, max_features=10000）** | **0.7562** | **0.7560** |

**字元 TF-IDF 模型 C 表現最好**：accuracy 0.7562、macro F1 0.7560，兩類表現平衡（concrete F1 0.7484、abstract F1 0.7636）。字元 n-gram 不依賴中文斷詞，改善了特徵覆蓋：訓練集 639/640 句、測試集 159/160 句有非零特徵；相較之下詞量 TF-IDF 在測試集只有 7/160 句有非零特徵。

**但這個分數不應解讀成模型「懂得」具體與抽象。** 測試標籤仍主要來自關鍵詞規則，模型可能只是更有效地重現規則中的詞彙模式。錯分例子顯示語境、敘述視角與混合語意仍是難題，例如「我也是人，他們想要吃我了！」既像具體事件，也帶有象徵性的恐懼。加上人工與規則一致率只有 82.76%，錯分不一定是模型造成，也可能是測試標籤本身有爭議。

**跨作者應用（〈秋河〉）**：111 句中模型預測 67 句 abstract、44 句 concrete，99 句有非零字元特徵。但 **105 句的 prob_concrete 落在 0.4–0.6**，平均值與中位數都接近 0.5——換句話說，模型雖然給了分類結果，多數句子的把握其實不高。〈秋河〉沒有人工金標，因此無法判斷這些預測對不對，也不能用這批結果證明模型能跨作者泛化。

**最主要的限制**是資料切分方式：只用單一作者訓練，且以句子隨機分 train/test，同一篇的句子可能同時出現在兩邊；〈狂人日記〉偏心理與象徵、〈社戲〉多場景描寫、〈阿Q正傳〉篇幅遠長於其他篇目，模型可能學到篇目特有線索，而非真正可移用的具體／抽象特徵。因此 0.7562 只能說明模型在這次隨機切分中表現如何，不能代表遇到新作者或新作品時也有同樣效果。未來應加入按篇目留出的測試、第二位標者獨立標註、以及〈秋河〉的人工金標，再考慮 BERT 類模型。

## 下載與重新實驗

### 專案結構

```text
data/raw/       原始文本複本及《呐喊》14 篇切分文本
data/           候選句、初始標註、平衡樣本、人工複核、訓練與分析句資料
scripts/        01–08 處理流程（含規則標註、平衡抽樣與 PDF 產生）
output/         模型指標、測試預測、〈秋河〉預測與 joblib 模型
docs/           GitHub Pages 互動式分析頁及其靜態資料
report.md       研究報告
report.pdf      提交用 PDF（由 scripts/08_build_report_pdf.py 產生）
requirements.txt
```

### 執行步驟

在專案根目錄安裝依賴並依序執行：

```powershell
pip install -r requirements.txt
python scripts\01_split_nahan.py
python scripts\02_prepare_candidates.py
python scripts\03_ai_label.py
# 先在 data\manual_check.csv 完成 my_label 人工複核，再繼續
python scripts\03b_balance_sample.py
python scripts\04_split_data.py
python scripts\05_train_eval.py
python scripts\06_apply_analysis.py
python scripts\07_build_dashboard.py
python scripts\08_build_report_pdf.py
```

`03_ai_label.py` 產生規則標註與 203 句人工複核表 `data/manual_check.csv`；請逐句填入 `my_label`（只接受 `concrete` 或 `abstract`），再執行 `03b_balance_sample.py`。若仍有空白或無效標籤，程式會停止，不會默默跳過人工複核。

`03b_balance_sample.py` 會先套用複核修正，再從兩類各抽 400 句（固定種子 42）；若任一類少於 200 句，程式會停止，不合成資料。

`04_split_data.py` 以 80/20 分層切分，`07_build_dashboard.py` 將互動頁資料與 CSV 匯出至 `docs/data/`，`08_build_report_pdf.py` 把 `report.md` 排版成 `report.pdf`（需 `reportlab`）。

## 資料來源與著作權

來源是專案根目錄提供的 `呐喊.txt` 與 `秋河_(郁達夫).txt`；程式將原始檔複製至 `data/raw/`，之後只讀取複本。魯迅（1881–1936）與郁達夫（1896–1945）的原作在作者逝世超過七十年後，通常屬公有領域；但未提供電子檔的版本、整理者或下載網址，因此此說明僅針對原作，不對特定數位版本的來源鏈作額外保證。報告與輸出只引用必要短句，不重刊全文。

## 已知限制

規則式標註容易把多義詞或只在特定語境成立的線索當成固定證據，且標籤不等同人工判讀；本次抽查一致率 82.76%，低於 85% 的參考門檻，已在平衡抽樣前套用複核標籤。全部訓練篇目仍來自同一作者，風格極端的篇目與篇幅特別長的〈阿Q正傳〉可能令模型利用篇目／作者線索，而非句子自身的抽象性。字元 n-gram 可緩解未斷詞造成的零特徵，但不能消除單一作者、篇目洩漏或規則標註偏誤。具體與抽象連續且可能並存；未來應加入作者分組測試、人工雙人標註、LLM 輔助標註或 BERT 類模型。
